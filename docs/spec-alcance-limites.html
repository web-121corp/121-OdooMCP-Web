01 / Resumen

RESUMEN PARA DECIDIR

Una herramienta para
entender la operación.

El MCP permite hacer preguntas sobre datos autorizados de Odoo desde un asistente conversacional. Su trabajo es reunir información y explicarla con contexto; no reemplaza Odoo ni ejecuta cambios.

SÍ HACE / 01

Responde preguntas

Busca clientes, reúne una vista 360, consulta ausencias y revisa capacidad, disponibilidad y horas de proyectos.

NO HACE / 01

No administra Odoo

No crea, edita, elimina, publica ni envía mensajes. El servidor está diseñado para leer, no para operar en nombre de una persona.

Quién mantiene la autoridad

Odoo sigue siendo la fuente original y quien decide el acceso. El MCP no fabrica permisos nuevos: consulta usando la identidad y las reglas que ya existen en Odoo.

Idea clave

Si una persona no puede ver un dato en Odoo, el MCP tampoco debería mostrarlo.

03 / Límites

LÍMITES FUNCIONALES

Leer mucho.
Cambiar nada.

Los límites no son una recomendación de uso: forman parte del diseño del servidor. Una petición que sale del alcance debe ser rechazada antes de llegar a Odoo.

  • No escribir registrosCrear, editar, borrar o duplicar datos está fuera del alcance.
  • No ejecutar accionesBotones, acciones de servidor, publicación y operaciones con prefijos de acción están bloqueados.
  • No enviar mensajesEl MCP no publica en chatter ni suscribe o desuscribe seguidores.
  • No saltar permisosACLs, reglas de registro, campos y compañías de Odoo continúan siendo la frontera de acceso.
  • No inventar datosSi el dato no está disponible o no está autorizado, la respuesta debe expresarlo.
  • No sustituir procesosNo reemplaza la interfaz de Odoo ni mantiene una copia maestra de la operación.

04 / Operación

ARQUITECTURA Y DESPLIEGUE

Una ruta corta,
con controles.

El MCP funciona como una capa intermedia. Recibe una pregunta, valida el contexto, consulta Odoo y devuelve el resultado sin exponer credenciales al asistente.

01

Asistente

LibreChat, ChatGPT o Flowise envía una pregunta.

02

MCP

Valida identidad, entrada y alcance de la consulta.

03

Odoo

Lee por XML-RPC con permisos reales.

04

Respuesta

Devuelve datos limpios, resumidos y trazables.

Ficha técnica en lenguaje claro

LenguajePython 3.12

La base de programación del servidor.

ContenedoresDocker + Compose

Empaquetado reproducible para desplegarlo.

Datos de controlPostgreSQL

Persistencia de sesiones, credenciales y auditoría.

Dónde se despliega

En un servidor controlado, normalmente detrás de HTTPS y un proxy o Cloudflare Tunnel. MCP y PostgreSQL viven en una red interna; el navegador no contacta directamente con n8n ni con Odoo.

Qué pasa si algo falla

Errores de autenticación, conexión o permisos se convierten en respuestas controladas. La operación no debe continuar como si el dato fuera válido.

05 / Seguridad

SEGURIDAD Y CONCEPTOS CLAVE

La confianza se
construye por capas.

Controles principales

  • API key tipo BearerLa credencial se verifica, se identifica mediante una huella y se usa solo en el contexto de la solicitud.
  • Secretos del lado del servidorLa llave de Odoo no queda en el navegador, en n8n, en URLs ni en la memoria del modelo.
  • Sesiones opacas y CSRFEl flujo embebido usa una sesión corta, revocable y protegida contra solicitudes forjadas.
  • Auditoría y límitesSe registran eventos relevantes y se limitan paginación, tamaño de entrada y alcance de consulta.
  • Red privadan8n y la base de control no se publican como servicios abiertos al navegador.

Glosario mínimo

MCP
Protocolo para conectar asistentes con herramientas externas de forma estructurada.
Tool
Una capacidad concreta que el asistente puede solicitar, como buscar clientes.
ACL
Reglas de Odoo que indican qué puede hacer o ver cada usuario.
Allowlist
Lista explícita de operaciones permitidas; lo que no está en ella se rechaza.
Read-only
Solo lectura: permite consultar, no modificar.
XML-RPC
Forma de comunicación usada para consultar Odoo desde otro servicio.

VEREDICTO

El MCP hace accesible el contexto de Odoo sin convertirse en una puerta para modificarlo.

Su alcance está en la conversación y el análisis; la autoridad y el cambio siguen en Odoo.
